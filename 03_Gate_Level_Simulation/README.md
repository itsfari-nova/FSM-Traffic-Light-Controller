## 1. Introduction

Gate-Level Simulation (GLS) is performed after RTL synthesis to verify the behavior of the synthesized design. Unlike RTL simulation, GLS operates on a gate-level netlist generated during synthesis.

In this stage, I used the SKY130-mapped traffic light controller netlist and a dedicated Verilog testbench to simulate the circuit using Icarus Verilog. GTKWave is used to visualize the resulting waveforms and inspect the behavior of the design signals.

## 2. Objectives

- Verify the synthesized traffic light controller through simulation.
- Examine the behavior of the SKY130-mapped netlist.
- Observe the RED, GREEN, and YELLOW signal transitions.
- Analyze the countdown and seven-segment display outputs.
- Generate and inspect the GLS waveform.
- Prepare the design for subsequent timing analysis.

## 📂 4. Design Files

| File | Description |
|---|---|
| `traffic_light_sky130_sim.v` | SKY130-mapped netlist used for simulation |
| `traffic_light_gls_tb.v` | Testbench for gate-level verification |
| `traffic_light_gls.vcd` | Waveform generated by the GLS testbench |

The testbench instantiates the `traffic_light` module and generates a clock, applies reset, and records the simulation signals.

## 5. Simulation Procedure

### Step 1: Navigate to the project directory

```bash
cd ~/traffic_light
```

### Step 2: Compile the mapped netlist and testbench

```bash
iverilog -o gls_sim traffic_light_sky130_sim.v traffic_light_gls_tb.v
```

This command compiles the design and testbench into a simulation executable named `gls_sim`, provided all required cell models are available.

If compilation reports undefined SKY130 cell modules, include the appropriate functional standard-cell Verilog models from your installed library.

### Step 3: Execute the simulation

```bash
vvp gls_sim
```

The testbench runs the simulation and writes the waveform data to `traffic_light_gls.vcd`.

Review the terminal output for the testbench messages and verification results.

### Step 4: Open the waveform

```bash
gtkwave traffic_light_gls.vcd
```

GTKWave displays the recorded signals and allows their transitions to be examined over simulation time.

## 6. Waveform Analysis

The generated VCD file records the signals declared in the GLS testbench.
Important signals to inspect include:

| Signal | Purpose |
|---|---|
| `clk` | Clock input |
| `reset` | Reset input |
| `red` | RED traffic light output |
| `green` | GREEN traffic light output |
| `yellow` | YELLOW traffic light output |
| `countdown[5:0]` | Countdown output |
| `seg_tens[6:0]` | Tens digit seven-segment output |
| `seg_units[6:0]` | Units digit seven-segment output |

The waveform can be used to examine reset behavior, state transitions, countdown updates, and display outputs.

## 7. RTL vs. Gate-Level Simulation Comparison

The RTL functional simulation waveform was compared with the Gate-Level Simulation (GLS) waveform generated using the SKY130-mapped netlist.

<img width="1920" height="940" alt="rtl vs gls waveform" src="https://github.com/user-attachments/assets/124ec5ce-9ea8-4170-b3d0-dcc1f4d52150" />

---
| Parameter | RTL Simulation | Gate-Level Simulation |
|---|---|---|
| Design | RTL Verilog | SKY130-mapped netlist |
| Traffic-Light Sequence | Expected behavior | Matches RTL |
| Countdown Timer | Correct countdown behavior | Matches RTL |
| Reset Operation | Works as expected | Matches RTL |
| Seven-Segment Display | Expected output behavior | Matches RTL |
| Overall Result | Reference behavior | Functionally consistent with RTL |

### Observations

- The red, green, and yellow signal transitions were consistent in both waveforms.
- The countdown timer behavior matched the RTL simulation.
- Reset behavior and seven-segment outputs were consistent.
- No visible functional differences were observed during the comparison.
