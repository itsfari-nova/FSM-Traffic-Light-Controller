## Overview

In this stage of my **FSM-Based Traffic Light Controller with Countdown Timer** project, I performed **Post-Layout Static Timing Analysis (STA)** using OpenSTA and the SKY130 HD standard-cell library.

After completing the physical design and routing stages, I analyzed the timing behavior of the final design using the routed database, timing constraints, and extracted parasitics.

The analysis covered setup timing, hold timing, worst slack, Worst Negative Slack (WNS), and Total Negative Slack (TNS) across 16 configured Process, Voltage, and Temperature (PVT) corners.

The main purpose was to understand the timing performance of the physically implemented circuit and identify any timing violations under different operating conditions.

## Objectives

- Perform timing analysis on the final routed design.
- Analyze setup and hold timing paths.
- Use extracted parasitics to account for physical interconnect effects.
- Evaluate timing across 16 PVT corners.
- Generate timing reports using a Tcl automation script.
- Understand WNS, TNS, and timing slack.
- Identify critical corners requiring further timing optimization.
- Understand the difference between pre-layout and post-layout timing analysis.

## Post-Layout STA Methodology

### Step 1 — Load the Final Design Database

I used the final routed design database generated by the OpenROAD physical design flow.

- **`6_final.odb`** — contains the final physical design representation.
- **`6_final.sdc`** — specifies timing constraints, including clock definitions and applicable input/output timing requirements.
- **`6_final.spef`** — contains extracted parasitic information for interconnects.

These files allow the timing engine to analyze the implemented design while accounting for the available physical and electrical information.

### Step 2 — Load the SKY130 HD Timing Library

I used the SKY130 HD standard-cell Liberty timing libraries for the configured PVT corners.

The timing libraries provide cell delay, timing-check, and electrical-characteristic information used by the STA engine.

### Step 3 — Run the Tcl Script

I used `sta_one.tcl` to automate the timing analysis.

The script loads the required library and design files, checks the timing setup, and generates detailed setup and hold reports along with slack and timing-violation metrics.

### Step 4 — Execute Multi-Corner Analysis

I ran the analysis for 16 configured PVT corners.

The combined summary reports that all 16 requested corner runs completed successfully, with zero failed runs. This indicates successful execution, not necessarily that every corner meets its timing constraints.

### Step 5 — Review and Interpret the Results

I reviewed the generated reports to identify the worst setup and hold slack and to determine which corners required further investigation.

The `ss_n40C_1v28` corner reported negative setup slack, making it an important result to investigate.

## Understanding Setup and Hold Timing

### 🔹 Setup Timing

Setup timing checks whether data reaches a sequential element sufficiently early before the active clock edge.

A setup violation occurs when data arrives later than the required arrival time.

Possible contributors include long logic paths, cell delays, interconnect delays, and the configured clock period.

### 🔹 Hold Timing

Hold timing checks whether data remains stable for the required time after the active clock edge.

A hold violation occurs when data changes too early relative to the receiving sequential element's clock.

Hold timing depends on minimum data-path delay, clock relationships, and physical implementation.

### 🔹 Timing Slack

Timing slack represents the margin between the required and actual timing of a path, according to the timing engine's reporting convention.

- **Positive slack:** The corresponding timing requirement is met for that path.
- **Negative slack:** The corresponding timing requirement is violated.
- **Zero slack:** The path is at the timing limit.

## Multi-Corner PVT Analysis

PVT stands for **Process, Voltage, and Temperature**.

- **Process:** Represents manufacturing variations affecting cell characteristics.
- **Voltage:** Represents the configured supply-voltage condition.
- **Temperature:** Represents the configured operating temperature.

Different combinations of these conditions can change cell delays and circuit timing. Multi-corner analysis evaluates the design under multiple conditions instead of relying on a single typical corner.

### Configured PVT Corners

| Process and temperature | Configured corners |
|---|---|
| FF, 100°C | `ff_100C_1v65`, `ff_100C_1v95` |
| FF, −40°C | `ff_n40C_1v56`, `ff_n40C_1v65`, `ff_n40C_1v76`, `ff_n40C_1v95` |
| SS, 100°C | `ss_100C_1v40`, `ss_100C_1v60` |
| SS, −40°C | `ss_n40C_1v28`, `ss_n40C_1v35`, `ss_n40C_1v40`, `ss_n40C_1v44`, `ss_n40C_1v60`, `ss_n40C_1v76` |
| TT, 25°C | `tt_025C_1v80` |
| TT, 100°C | `tt_100C_1v80` |

- **FF:** Fast-process corner
- **SS:** Slow-process corner
- **TT:** Typical-process corner

The corner names encode the configured process, temperature, and voltage. The library configuration determines the exact electrical models used in each analysis.

## Pre-Layout vs Post-Layout STA

Pre-layout and post-layout STA evaluate timing at different stages of the design flow.

<img width="1145" height="1021" alt="pre_sta vs post_sta" src="https://github.com/user-attachments/assets/21ae14a3-a155-4e9c-b35a-a8eac66775fd" />


| Aspect | Pre-Layout STA | Post-Layout STA |
|---|---|---|
| Design stage | Before completed physical routing | After physical implementation and routing |
| Design representation | Synthesized design and available physical estimates | Final physical design database |
| Interconnect parasitics | Estimated or idealized, depending on setup | Extracted parasitics when provided and correctly loaded |
| Main purpose | Evaluate timing before final physical implementation | Evaluate timing with physical implementation effects |
| Timing behavior | Based on the pre-layout models and assumptions | Includes the modeled physical interconnect effects |

## Tcl Automation Script

The `sta_one.tcl` script automates the main steps of the timing analysis.

Its operations include:

1. Identifying the final design database and selected PVT corner.
2. Loading the appropriate Liberty timing library.
3. Reading the final physical design database.
4. Loading the timing constraints.
5. Loading the extracted parasitic data.
6. Checking the timing setup.
7. Generating setup and hold timing reports.
8. Generating worst-slack, WNS, and TNS reports.

The script uses environment variables such as `FLOW_HOME`, `CORNER`, and `REPORT_DIR`. These must be configured appropriately when running it in another environment.

### Report Descriptions

- `summary.txt` — summary for the typical timing corner.
- `summary_16_corners.txt` — combined summary of the configured multi-corner runs.
- `setup_timing.rpt` — detailed setup timing paths.
- `hold_timing.rpt` — detailed hold timing paths.

### Script Description

- `sta_one.tcl` — Tcl script used to load the design and timing data, perform timing checks, and generate reports.
