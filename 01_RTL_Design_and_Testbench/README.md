## 1. RTL Implementation

The RTL implementation is contained in `traffic_light.v`.

The Verilog module `traffic_light` describes the sequential behavior of the controller using clock-driven logic, an FSM, countdown functionality, and seven-segment display outputs.

The design uses parameters to configure the clock frequency and nominal duration of each traffic light phase.

## 2. FSM Implementation

The controller operates through three traffic light states:

| State | Active Output | Default Duration Parameter |
|---|---|---|
| RED | `red = 1` | `RED_SECONDS = 30` |
| GREEN | `green = 1` | `GREEN_SECONDS = 30` |
| YELLOW | `yellow = 1` | `YELLOW_SECONDS = 5` |

### State Transition Sequence

```text
RED → GREEN → YELLOW → RED
```
<img width="1000" height="600" alt="image" src="https://github.com/user-attachments/assets/c69a8442-496e-4ea6-9f45-3780f148a1c5" />

The FSM advances according to the phase-completion conditions implemented in the RTL. The state and output behavior can be examined during simulation.

## 3. Countdown Timer and Display Logic

The design includes configurable timing parameters and outputs for the countdown and seven-segment display.

| Parameter | Default Value | Description |
|---|---:|---|
| `CLK_FREQ_HZ` | 50,000,000 Hz | Clock-frequency parameter. |
| `RED_SECONDS` | 30 | RED phase duration parameter. |
| `GREEN_SECONDS` | 30 | GREEN phase duration parameter. |
| `YELLOW_SECONDS` | 5 | YELLOW phase duration parameter. |

The module provides a six-bit `countdown` output and two seven-bit display outputs:

- `seg_tens` — tens-digit display pattern.
- `seg_units` — units-digit display pattern.

The seven-segment outputs use active-low encoding with segment order `a, b, c, d, e, f, g`.

## 4. Module Interface

The top-level module is named `traffic_light`.

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `clk` | Input | 1 bit | Clock input for sequential operation. |
| `reset` | Input | 1 bit | Active-high reset input. |
| `red` | Output | 1 bit | RED traffic signal. |
| `green` | Output | 1 bit | GREEN traffic signal. |
| `yellow` | Output | 1 bit | YELLOW traffic signal. |
| `countdown` | Output | 6 bits | Countdown value. |
| `seg_tens` | Output | 7 bits | Tens-digit display pattern. |
| `seg_units` | Output | 7 bits | Units-digit display pattern. |

## 5. Source Files

### `traffic_light.v`

Contains the RTL design, including the module interface, parameters, FSM control, countdown logic, traffic signal outputs, reset behavior, and seven-segment display logic.

### `traffic_light_tb.v`

Contains the testbench used to apply clock and reset stimulus, observe output signals, and check the behavior defined by the test scenarios.

## 6. RTL Simulation

RTL simulation was performed using **Icarus Verilog**.

Run the following commands from the directory containing the two Verilog files.

### Step 1: Compile the RTL and testbench

```bash
iverilog -o rtl_sim traffic_light.v traffic_light_tb.v
```

This compiles the design and testbench into the simulation executable `rtl_sim`.

### Step 2: Execute the simulation

```bash
vvp rtl_sim
```

This runs the compiled simulation and prints the messages generated by the testbench.

The testbench output should be checked to confirm the behavior and results of the implemented test cases.

## 7. Waveform Generation and Analysis

The testbench can generate a Value Change Dump (VCD) file to record signal transitions during simulation.

The waveform file used in this project is:

`traffic_light.vcd`

### Open the waveform in GTKWave

```bash
gtkwave traffic_light.vcd
```

GTKWave displays the recorded signal transitions against simulation time. Add the required signals to the waveform viewer to examine the controller's behavior.

> **Note:** The testbench must contain the appropriate `$dumpfile` and `$dumpvars` statements for the VCD file to be generated. The simulation should be run before opening the waveform.

## 8. Signals Observed

The following signals are available at the top-level module interface and can be inspected in GTKWave.

| Signal | What to Examine |
|---|---|
| `clk` | Clock pulses and sequential timing. |
| `reset` | Initialization behavior. |
| `red` | RED phase activation and deactivation. |
| `green` | GREEN phase activation and deactivation. |
| `yellow` | YELLOW phase activation and deactivation. |
| `countdown` | Changes in the countdown value. |
| `seg_tens` | Tens-digit display pattern changes. |
| `seg_units` | Units-digit display pattern changes. |

The expected state sequence is **RED → GREEN → YELLOW → RED**, according to the implemented FSM. The actual transitions and countdown values should be confirmed from the simulation waveform.

## 10. Summary

This stage covers the RTL implementation and functional verification of the FSM-based traffic light controller. The Verilog testbench is used to simulate the 

design, while GTKWave helps inspect signal transitions and countdown behavior. The verified RTL design provides the foundation for the next stages: synthesis, 

gate-level simulation, and timing analysis.
